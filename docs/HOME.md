# Запуск удома, бо хостингу Vinted більше не дає

## Що сталось

Заміряно, не припущено. В один і той самий момент:

```
з домашньої мережі:   головна 200, каталог 200, 192 лоти
з Render:             головна 403, каталог 403, читань 0
```

Render за дві години роботи не прочитав ЖОДНОЇ стрічки: `ok: 0` на обох
ринках, 255 запитів пропущено під запобіжником, знахідок нуль. При цьому той
самий код, той самий конфіг, та сама секунда - з іншої адреси працює.

Це блок адреси, і формою запиту він не лікується. Перевірено все, що можна
було перевірити: заголовки як у справжнього браузера дають той самий 403,
куки не потрібні, кількість `brand_ids[]` ми вже полагодили (її межа - 18, і
це була справжня окрема поломка). Лишається сама адреса.

Чому саме вона: безкоштовний Render роздає вихідні адреси в спільне
користування. Через них ходить не тільки наш бот, і Vinted бачить з однієї
адреси трафік сотень скриптів. Плюс наші ж кілька діб по 403 після появи
межі на `brand_ids[]` репутацію не покращили.

## Що з цим можна зробити

**Проксі** - не варіант за цими грошима. Бот качає близько 60 ГБ на місяць;
резидентні проксі коштують кілька доларів за гігабайт, тобто сотні доларів
на місяць. Дешеві проксі з дата-центрів заблоковані рівно так само, як
Render.

**Інший хостинг** - те саме завтра. Vinted ріже діапазони дата-центрів, а не
конкретну адресу Render.

**Домашній інтернет** - працює, безкоштовно і просто. Саме такий трафік
Vinted і має пропускати: це адреса, з якої люди заходять на сайт. 60 ГБ на
місяць для домашнього каналу - дрібниця, і ніякого ліміту трафіку немає.

## Як підняти вдома

Треба щось, що працює цілодобово: робочий ПК, старий ноут, Raspberry Pi.
Docker уже налаштований, тому це три команди.

```bash
git clone <репозиторій>
cd ERACLOUD-2.0
cp .env.example .env     # сюди TELEGRAM_BOT_TOKEN
docker compose up -d
docker compose logs -f   # подивитись, що пішло
```

Перевірити, що читає:

```bash
curl -s localhost:10000/health | python3 -m json.tool | head -40
```

Дивитись треба на `fetch`: `ok` має рости, `403` стояти на нулі. І на
`silent_for` - скільки секунд не було жодного успішного читання.

### Що змінюється порівняно з Render

| | Render | удома |
|---|---|---|
| `DATABASE_URL` | потрібен Neon, бо диска немає | не потрібен, SQLite у `./data` переживає перезапуск |
| бюджет трафіку | 90 ГБ, інакше сервіс зупиняють | не потрібен, постав `monthly_traffic_gb: 0` |
| самопінг | тримає інстанс від засинання | не потрібен, але не заважає |
| адреса | спільна, заблокована | своя, робоча |

Тобто вдома зникають одразу три проблеми, навколо яких ми тут танцювали:
втрата бази при кожному деплої, ліміт трафіку і блок.

### Якщо ПК вимикається на ніч

Нічого страшного: при розриві довшому за три хвилини бот розуміє, що був
простій, і першим циклом бере тільки свіже, а не вивалює добу історії одним
залпом. Але тоді й лоти за ніч пройдуть повз - для цього й потрібне щось,
що не вимикається.

## Поки працює Render

Бот звідти нічого не читає, але тепер хоч каже про це: якщо двадцять хвилин
поспіль не вдалось прочитати жодної стрічки, в Telegram приходить
повідомлення з причиною (403 і скільки їх). Раніше це виглядало просто як
"алертів нема", що плутається з "нема вигідних лотів" - а лікуються ці два
стани зовсім по-різному.
